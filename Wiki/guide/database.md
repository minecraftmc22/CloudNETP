# 数据库容灾

`DATABASE_URL` 指向的**主库是唯一真相**；本地 SQLite（`storage/db/fallback.db`）是它的
实时副本和逃生舱。主库抖动（远程 MySQL、Tailscale 链路）时，服务不会整个挂掉。

## 三个阶段

| 阶段 | 行为 |
| --- | --- |
| 正常 | 每 `DB_MIRROR_INTERVAL` 秒把主库全表镜像进 SQLite（审计日志只留最近 5000 条） |
| 主库断连 | 看门狗按 `DB_PROBE_INTERVAL` 探测，失败后新请求全部改走 SQLite，并写 `__failover_dirty` 标记；文件本体在磁盘，不受影响 |
| 主库恢复 | 先把降级期间的变更**回迁**主库（按主键覆盖），成功后切回主库并立即重新镜像 |

降级期间重启也没关系：启动时发现 `__failover_dirty` 会先回迁再镜像，不会把这段时间的写入盖掉。

## 几条边界

- 按**单实例部署**设计。多实例同时写主库时，「以 SQLite 为准」的回迁会打架 —— 这种部署请把
  `DB_FALLBACK_ENABLED` 关掉。
- 如果 fallback 是**从未镜像成功过**的新库（`__failover_mirror_at` 不存在），回迁只补缺失行、
  绝不覆盖主库：宁可少迁，不能拿空库盖掉线上数据。
- 切换瞬间正在飞行的请求可能失败一次（旧连接已断），重试即可。
- 内部标记键都以 `__` 开头，只存在 fallback 库，不会被同步进主库。
- 镜像与回迁都按表逐行 upsert、单表一个事务；中途失败下一轮重试，不会写坏数据。

## 在后台管理

「管理后台 → 系统设置 → 数据库」卡片：

![数据库卡片](/images/admin-db.jpg)

显示当前服务库、主库连接串（密码脱敏）、探活延迟、容灾副本的路径 / 体积 / 可信状态，
以及看门狗的探测与镜像间隔。三个按钮：

| 按钮 | 作用 |
| --- | --- |
| 刷新配置 | 重读 `.env` 里的 `DATABASE_URL` 与容灾参数，就地更新配置、重建连接池并重新探活；连接串变了会一起生效 |
| 重新连接 MySQL | 丢弃旧连接池重新握手；若当前跑在 SQLite，先回迁本地数据，**回迁成功才切回**，连不上就报错并保持现状 |
| 重新连接 SQLite | 先镜像一份最新副本，再切到本地库服务；切过来后**暂停自动回切**（否则看门狗很快又切回去），点「重新连接 MySQL」或重启进程才恢复 |

刷新与切换都会写审计日志（`admin_db_refresh` / `admin_db_reconnect`）。

::: warning 环境变量优先级更高
「刷新配置」只覆盖从 `.env` 读到的值。用 systemd / 命令行显式 `export` 的同名变量优先级更高，
不会被文件覆盖 —— 想彻底改就用环境变量管理工具改。
:::

## 相关环境变量

| 变量 | 说明 |
| --- | --- |
| `DATABASE_URL` | 主库地址；`sqlite:///./dev.db` 表示本来就用本地库（此时容灾无意义） |
| `DB_FALLBACK_ENABLED` | 是否启用降级（多实例部署请关） |
| `DB_PROBE_INTERVAL` | 探活间隔秒数，`0` 表示只在启动时选库、运行期不切换 |
| `DB_MIRROR_INTERVAL` | 主库 → SQLite 镜像间隔秒数，`0` 表示不做周期镜像 |
| `DB_CONNECT_TIMEOUT` / `DB_TIMEOUT` | 远程库连接与读写超时（秒），链路慢时调大 |
