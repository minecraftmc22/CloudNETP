# 关于页与致谢

侧栏「关于」把「这是什么、用了什么、谁做的、改了什么」放在一页：版本号、主要能力、技术栈、
作者与仓库、开源致谢、贡献者、更新记录。不需要额外权限，普通用户也能看。

## 顶部：版本与检查更新

- 应用名旁边是当前版本号（和登录页、`/api/version` 一致），右上角还有数据库模式徽章：
  「主库 · MySQL」或「降级运行 · SQLite」。
- **检查更新**：只读地比对 GitHub 上的版本号，不会改任何文件；有新版本会在下面给出提示与链接。
- **复制地址**：把 `http://<主机>/` 复制到剪贴板，方便发给同局域网的人。
- 三个按钮下面写着当前登录的账号，确认「我现在是谁」。

真正执行更新（`git pull --ff-only` + 重启）在[管理后台](/guide/admin.md)的「版本更新」卡片里，
要求是 git 检出、没有未提交改动；Docker / 压缩包部署只能重新拉镜像或覆盖文件。

## 主要能力 / 技术栈

两张卡片分别是功能清单与依赖栈，点进去的细节在对应文档里：文件与上传见
[文件管理](/guide/files.md)，预览见[在线预览](/guide/preview.md)，以此类推。
技术栈只列名字与用途，不展开版本号——真正的版本以 `requirements.txt` 和 `static/vendor/` 为准。

## 作者与仓库

| 入口 | 去哪 |
| --- | --- |
| 意见反馈 | 站内提交给管理员，处理状态在[意见反馈](/guide/admin.md)里看 |
| GitHub 仓库 | 源码与 Release 镜像 |
| 提交 Issue | Bug 或改进建议直接发到仓库 |
| CDP娘版权声明 | 看板娘的版权说明（`/live2d/model/CDP/COPYRIGHT.md`） |

## 开源致谢

「感谢」卡片列出实际用到的开源项目，按后端 / 前端分组，每个都带**用途**、**许可证**与仓库链接，
点进去就是项目主页。

| 分组 | 包含 |
| --- | --- |
| 后端 | FastAPI、Uvicorn、SQLAlchemy、PyMySQL、cryptography、Pillow、mutagen、qrcode |
| 前端（随仓库内置，不走 CDN） | ArtPlayer、hls.js、dash.js、JSZip、docx-preview、SheetJS、PixiJS、qrcode-generator |

::: warning Live2D Cubism SDK 不是开源软件
看板娘的模型运行时用的是 Live2D 的专有 SDK，卡片上单独标成「Live2D 专有许可」（橙色标签），
使用时请遵守 [Live2D 的 SDK 许可](https://www.live2d.com/sdk/)，不要把它当开源组件再分发。
:::

其它项目均按各自许可证使用，完整条款以各项目仓库为准。漏了哪个正在用的项目，欢迎提 Issue / PR
补上——README 的「致谢」章节是同一份名单。

## 贡献者

名单来自 GitHub 的 contributors 接口，展示方式做了三层兜底：

1. 打开页面先用**内置快照**渲染，离线、被墙或 GitHub 限流时也能正常显示，不会空白；
2. 随后异步拉最新名单替换，结果在浏览器里缓存 **24 小时**（匿名接口每小时只有 60 次配额，
   没必要每开一次关于页就打一次）；
3. 超时 6 秒、任何失败都静默保留快照，不弹错误。

只统计人，`dependabot` 这类 Bot 会被过滤；每一项显示首字母头像、GitHub 用户名与提交次数，
点进去是对方主页。底部「在 GitHub 查看贡献者与提交记录」跳到完整图。

想手动刷新：清掉浏览器 localStorage 里的 `cn:contributors`，再打开关于页。

## 更新记录

按版本倒序排列，每条写明这个版本改了什么、为什么改。默认只展开最近 **4 条**，点「展开全部 N 个版本」
看完整历史。

记录正文**只提供中文原文**，不随界面语言切换：它更像变更日志而不是界面文案，英文界面下卡片顶部
会有一行说明。发版时若不补记录，`scripts/changelog_check.py` 会直接报错。
