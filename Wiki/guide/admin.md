# 管理后台

管理员登录后侧栏出现「管理后台」。八个页签：概览、用户、举报审核、申诉审核、意见反馈、审计日志、邮箱服务、系统设置。

![管理后台概览](/images/admin.jpg)

## 概览

- **运行状态**：版本、运行时长、数据库类型与当前模式（主库 / 降级 SQLite）。
- **存储**：总容量、已用、文件数与用户数，条状图看占用比例。
- **最近操作**：最新几条审计记录，点进去可到完整日志。
- **占用排行**：谁用得最多，方便找超额用户。

## 用户管理

![用户管理](/images/admin-users.jpg)

列表带搜索与分页，每行可以：

| 操作 | 说明 |
| --- | --- |
| 调整配额 | 单独设 GB 数，改完立即生效（已超额的部分不会被删） |
| 封禁 / 解封 | 封禁时要填**原因**并选**时长**（1 / 3 / 7 / 30 天或永久）。在线的用户会立刻看到封禁弹窗（原因、封禁时间、解封时间、去申诉），不在线的下次登录会被带到申诉页；到期自动解封 |
| 重置密码 | 生成新密码，用户下次登录用新密码；不会发邮件 |
| 设置角色 | 普通用户 / 管理员 / 超级管理员（只有超管能操作） |
| 级联删除 | 删账号连同其全部文件、分享、回收站记录；需要二次确认 |

### 角色与权限

| 角色 | 怎么来的 | 能做什么 |
| --- | --- | --- |
| 普通用户 | 自己注册 | 自己的文件、分享、快传 |
| 管理员 | 超管在用户页设置 | 进管理后台、看用户与审计日志、调配额 / 重置密码 / 封禁、改系统设置 |
| 超级管理员 | **第一个注册的账号自动成为**；超管也能再提别人 | 管理员的一切 + 增减管理员、设置或取消超管 |

默认限制（都是服务端拦截，绕过界面直接调接口也一样）：

- 普通管理员**不能把任何人设为管理员**，也不能取消别人的管理员；
- 普通管理员**不能取消超管**，也不能把超管降成普通用户；
- 超管的密码重置、封禁、删除对普通管理员一律不可用（防止接管超管账号）；
- 超管不能取消自己、不能把自己降级——避免管理员列表里一个能管的人都不剩；
- 一个超管想退回普通用户，得由**另一个超管**先取消他的超管身份（会保留管理员身份），再取消管理员。

想在同一套数据库里放多个超管（比如运维账号），直接改库即可：

```sql
UPDATE users SET is_super = 1 WHERE username = 'ops';
```

下一次启动会顺手把 `role` 补齐成 1；`is_super=1` 本身就足以进管理后台，不必等重启。

## 申诉审核

被ban的用户可以在申诉页提交说明，条目出现在这里：

- 顶部按「待审核 / 已通过 / 已驳回 / 全部」筛选；
- 每条显示申诉人、申诉内容、当时的封禁原因与解封时间，以及账号当前是否仍在封禁；
- **通过并解封**：立即解除封禁、清空原因与到期时间，用户下一次请求就能回到网盘；
- **驳回**：账号继续封禁，可以附一句说明，显示在用户的申诉页，用户可以补充信息再次申诉；
- 每人 24 小时内最多提交 3 条申诉，已有「审核中」的条目时重复提交会被拦下（409）；
- 管理员成员的申诉只有超管能审（避免普通管理员互相放行）。

用户在线时被封会马上收到弹窗；如果当时不在线，下一次在登录页登录会直接跳到申诉页。
临时封禁到期会自动解封，不需要手动操作。

## 举报审核

访客在分享页可以举报内容。这里列出举报条目，能直接看到被举报文件的预览与举报理由，
处理方式为「忽略」或「下架分享」。

## 意见反馈

用户在「关于」页提交的建议 / 问题汇总在这里，只有管理员可见。可以标记为已处理，
反馈内容、联系方式、提交人都会显示。

## 审计日志

![审计日志](/images/admin-logs.jpg)

覆盖 80+ 类动作：登录（含被封账号尝试登录）、注册、上传、下载、删除、还原、移动、复制、改名、
分享创建 / 下载、快传收发与取件、WebDAV 写入、后台设置变更、数据库切换、封禁与申诉审核、
看板娘工具调用与 AI 配置等。每条记录带操作者、动作、详情、IP 与时间。

- 支持按动作、用户、时间范围筛选与分页；动作下拉里每一项都带累计条数（如「看板娘调用工具（128）」），
  方便直接看出哪类操作最多。
- 审计动作名会按界面语言显示；没翻译的动作退回原始名称，不会出现 `审计动作:xxx` 这种前缀。
- 「系统设置 → 维护」里可以按天数清理旧日志，也可以手动清空。

## 系统设置

| 卡片 | 能改什么 |
| --- | --- |
| 站点 | 站点名称、公告、是否开放注册 |
| 搜索引擎优化（SEO） | 收录开关、标题、描述、关键词、分享图与公开地址，见下节 |
| 找回密码兜底联系 | 管理员邮箱与 QQ，登录页「忘记密码」会显示 |
| 配额与上传 | 新用户默认配额、单文件上限、分片大小、回收站保留天数 |
| 快传取件码 | 最长有效期、单个文件下载次数上限、过期后文件保留天数、生成后是否自动复制分享文案与文案模板，以及立即清理过期文件 |
| 版本更新 | 是否自动检查更新、手动更新按钮（git fast-forward + 重启） |
| 数据库 | 当前服务库、探活延迟、容灾副本状态，以及刷新配置 / 手动切换，见[数据库容灾](/guide/database.md) |
| 维护 | 清理审计日志、孤儿文件扫描（磁盘上有文件、数据库没记录的那种残骸）、运行环境路径 |

::: tip 孤儿文件扫描
上传中断、数据库回滚都可能留下「磁盘上有 blob、但没有任何记录引用」的残骸。扫描会对比
磁盘与数据库，列出可回收的字节数，确认后清理。正常文件不会被误删。

反过来的情况——数据库里有记录、却没有任何文件指向它——在[存储空间](#存储空间)页处理。
:::

## 存储空间

「存储」页把占用与清理集中在一处：物理文件数、磁盘水位、无人引用规模、快传占用，往下是三段操作。

### 清理无人引用的文件

`blobs` 表里还有记录、但 `nodes` 表已经没有任何节点指向它的文件。正常删除会把引用归零的记录一起删掉，
历史数据与并发写入仍可能留下这种条目：永远用不上，却一直占磁盘。

- 先「扫描并清理」只做统计，弹窗报出条数与可释放空间，确认后才真删，记录与磁盘文件一起清。
- **被举报拉黑的原件会保留**——审核复核还要预览原件。
- **最近 1 小时新写入的跳过**：上传是「先落盘、再登记」，这中间有个很短的窗口，别把正在传的删了。
  自动清理用 24 小时保护期，更保守。
- 引用计数漂移（记录说有人用、节点表里找不到）也会被清掉，扫描结果里的 `drift` 就是这个数。

### 自动清理

- 打开开关、选一个整点（服务器本地时间），每天到点自动跑一次；清理项两项独立开关：
  无人引用的文件、失效的快传文件。
- 后台线程每分钟检查一次，**到点且当天没跑过**才执行，所以重启或同一天多次唤醒都不会重复清理。
- 跑完把时间与各清了多少写进「上次运行」，重启也不丢。
- 「立即执行一次」会先把当前表单保存下来再执行，改了时间没点保存也不会用旧配置跑。

### 清理失效的快传文件

过期 / 撤销超过保留天数的取件码文件，连同物理文件一起回收。**只删快传自己存的副本**，
用户从「我的文件」里选来生成取件码的那些文件属于他自己的网盘，不会被删。
保留天数在「系统设置 → 快传取件码」里调。

## 邮箱服务

「绑定邮箱」要发验证码，就得先在这里把发信通道配好。保存即生效，不用改 `.env`、也不用重启。

| 通道 | 怎么走 |
| --- | --- |
| BillionMail | 自建发件网关，调它的 HTTP 发件 API。地址填部署的根地址（`https://mail.example.com`），Key 在 BillionMail 后台的「API」页生成 |
| SMTP | 直接连邮箱服务器。465 是隐式 SSL，587 是明文起手再 STARTTLS，25 明文只建议内网中继用；加密方式与端口要配对 |

BillionMail 还有两种调用方式：

- **模板 API**：主题、正文、发件人都在 BillionMail 后台的「API」模板里配，本站只把验证码当变量传过去
  （模板里写 `{{.API.code}}`，变量名可在卡片里改）。想要统一走自己的邮件模板就选它。
  不知道模板怎么写就点卡片里的「下载模板」：导出的 HTML 直接粘进 BillionMail 的模板编辑器即可，
  里面的变量位跟「验证码变量名」一致，改过变量名要重新下载一份。
- **直传 subject + html**：主题和正文由本站拼，适合没有现成模板、或者想让验证码邮件长成站点风格的情况。

填写要点：

- **测试发信**用的是表单里**还没保存**的值，可以先试通再保存；它不受「启用邮箱服务」总开关影响。
- API Key 与 SMTP 密码加密存在服务端，接口只回掩码。输入框**留空 = 不改**，要清掉得勾
  「清除已保存的…」，否则每次保存都会把凭据抹掉。
- 普通字段留空 = 继续用 `.env` 的 `MAIL_*`；「恢复 .env 配置」会一次性清掉这里保存的全部覆盖。
- 卡片右上角的状态是算出来的：参数齐了显示「已就绪」，登录页的「获取验证码」也才会出现。

::: tip 发信失败不会白扣冷却
验证码在发信前就写进服务端内存并计了限流；如果 SMTP / API 报错，这次写入会被精确撤回，
失败后立刻可以重试，不会被 30 秒冷却卡住。
:::

## SEO

首页的 `<title>`、description、`og:*`、canonical 由**服务端**直接写进 HTML——搜索引擎和
微信 / Telegram 的链接预览都不执行 JS，只认首屏源码里有什么。

| 字段 | 说明 |
| --- | --- |
| 允许搜索引擎收录 | 总开关，**默认关闭**。关着时首页输出 `noindex,nofollow`，robots.txt 整站 `Disallow: /`，sitemap 返回 404 |
| SEO 标题 | 留空沿用「站点名称 · 樱色云盘」 |
| 站点描述 | 搜索结果里标题下面那两行，建议 80 字以内 |
| 关键词 | 英文逗号分隔。现代搜索引擎基本不看，填了也无妨 |
| 分享图地址 | `og:image` 的图片直链，建议 1200×630 |
| 公开地址 | 用于 canonical 与 sitemap，例如 `https://pan.example.com`；留空按访问域名推断（反向代理后可能不准） |

卡片下方是一条「搜索结果预览」，边改边看大概长什么样；`robots.txt` 和 `sitemap.xml` 都能一键打开。

::: warning 私链页面永不收录
`/s/<token>` 分享页、`/pickup` 取件页、`/drop/<token>` 扫码直传页都硬编码了
`noindex, nofollow`，不受这个开关影响——它们本来就只该被拿到链接的人看到。
:::

## 版本更新

- 关于页有「检查更新」，任何人都能点，只读地比对版本号，不会改代码。
- 后台「版本更新」卡片可以开自动检查提示，也可以直接点更新：只做 `git pull --ff-only`，
  然后按 `CLOUDNETP_RESTART_CMD`（或内置 `scripts/restart_helper.py`）重启。
- 前提：**git 检出、main 分支、工作区没有未提交改动**。私有仓库要在 `.env` 配只读
  `UPDATE_TOKEN`（fine-grained PAT，Contents: Read），否则匿名请求会 404。
- Docker / 压缩包部署不适用，请在宿主机重新拉取或覆盖文件。
